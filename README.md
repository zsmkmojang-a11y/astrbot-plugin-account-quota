# codex额度查询及福利重置预测

支持监测codex和deepseek额度以及重置卡状态和自然刷新时间，预测下次福利重置时间。

## 安装与前提

### 通过官方插件市场（推荐）

在 AstrBot 的插件市场搜索 **codex额度查询及福利重置预测** 或 `astrbot_plugin_account_quota`，点击安装。

### 通过 GitHub 仓库安装

在 AstrBot 插件管理页选择从链接安装，填写仓库地址：

```text
https://github.com/zsmkmojang-a11y/astrbot-plugin-account-quota
```

### 本地安装

在仓库页面通过 **Code → Download ZIP** 下载，或使用提供的 `astrbot_plugin_account_quota.zip`，然后在 AstrBot 插件管理页上传 ZIP；也可以将仓库内容放入 AstrBot 的 `data/plugins/astrbot_plugin_account_quota/` 目录，保证该目录直接包含 `main.py` 和 `metadata.yaml`。

安装后重新加载插件，在 AstrBot 中将自己的平台用户 ID 配置为管理员，默认仅管理员可以查询账号额度和余额；公开 Reset 预测与历史允许所有用户查询。

插件使用 Python 3.12+，接口按 AstrBot 官方 `v4.28.1` 源码核对。HTTP 客户端使用 AstrBot 自带的 `aiohttp`，不增加额外依赖。

## 查询指令与自然语言

| 指令 | 查询范围 |
| --- | --- |
| `/额度` | Codex + DeepSeek |
| `/codex额度` | Codex |
| `/deepseek余额` | DeepSeek |

`/` 是常见的 AstrBot 唤醒前缀；如果你的唤醒前缀不同，请使用实际配置的前缀。

强唤醒词假设为 `小助手`，可以发送：

```text
小助手 帮我查一下额度
小助手 查一下 Codex 额度
小助手 DeepSeek 还剩多少钱
小助手 查看 Codex 和 DeepSeek 的额度
```

也支持 @ 机器人后发送上述查询。私聊是否需要唤醒词遵循 AstrBot 自身设置。插件读取 AstrBot 的唤醒标记，不另设唤醒词；请先在 AstrBot 配置你的强唤醒前缀。

自然语言匹配明确、完整的查询短语，不调用 LLM 做意图识别。“额度怎么计算”“不要帮我查一下额度”“帮我查一下额度，然后写诗”等不会触发查询。普通未唤醒的群聊消息不会触发。你可以在配置中关闭自然语言查询，命令仍然有效。

查询命中后仅回复一次，并停止该消息继续调用模型。查询失败和权限不足也会直接返回提示，不需要 DeepSeek 有余额才能执行查询。

Codex 和 DeepSeek 查询开关默认均开启，`/额度` 和合并自然语言查询只获取开启的来源。单独查询关闭的来源时提示“查询已关闭喵”；两者都关闭时只返回关闭提示，不调用接口或模型，也不展示旧缓存。

每个额度查询结果附数据时间，时间按北京时间显示。缓存结果沿用原数据时间，倒计时也是该次查询时计算的值。开启两个来源时并发查询，一方失败不影响另一方；相同来源的同时查询会合并，不同 DeepSeek Key 的缓存隔离。

## DeepSeek：余额监测与配置

### 功能

通过 DeepSeek 官方 `/user/balance` 查询所选 API Key 对应账号的总可用余额、充值余额和赠金，保留小额余额精度。默认显示人民币余额；开启 USD 选项后也显示接口返回的美元余额，不做汇率换算。接口只返回 USD 且显示开关关闭时，会提示余额已隐藏，不把缺少人民币余额当作 0。

人民币总余额严格小于 **10 元** 时，在查询结果后追加默认提醒：

> 该充蓝色大肥鱼了喵，要吃不起白饭了。

可修改提醒文案和附图；USD 余额不参与人民币不足 10 元的判断。

### 配置步骤

1. 在 AstrBot 中配置 **DeepSeek 官方 API** 提供商，填写官方地址和 API Key。
2. 保持“启用 DeepSeek 余额查询”开启；有多个官方提供商时，填写 `deepseek_provider_id` 指定账号。
3. 按需开启 USD 显示、修改余额不足文案，保存配置并重载插件。
4. 使用 `/deepseek余额` 或唤醒后说“帮我查一下 DeepSeek 余额”。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `deepseek_query_enabled` | `true` | 启用 DeepSeek 余额查询；关闭后不读取凭据或调用余额接口。 |
| `deepseek_provider_id` | 空 | 指定 AstrBot 中的 DeepSeek 官方提供商 ID，复用其凭据。 |
| `deepseek_show_usd` | `false` | 显示官方接口返回的 USD 余额；默认关闭，不进行汇率换算。 |
| `deepseek_low_balance_reply` | 该充蓝色大肥鱼了喵，要吃不起白饭了。 | DeepSeek 余额不足提醒，留空隐藏文字。 |

关闭查询开关后不读取 DeepSeek 凭据，也不调用余额接口；这不会改变 AstrBot 中模型提供商本身的启用状态。

DeepSeek 提供商选择顺序：

1. 配置了 `deepseek_provider_id` 时，使用指定提供商。
2. 否则，优先使用当前会话的官方 DeepSeek 提供商。
3. 当前会话不是 DeepSeek 时，使用唯一一个已加载的官方 DeepSeek 提供商；没有或有多个候选时提示指定 ID。

仅认可 HTTPS 的 `api.deepseek.com`（根路径、`/v1` 或 `/beta`）；第三方中转站即使模型名含 DeepSeek，也不会被当作官方账户查询。API Key 优先取提供商当前 Key；无法取得且存在多个不同 Key 时提示配置，避免猜测账号。余额属于所选 Key 对应的账号，不属于单个模型。

插件只向固定官方余额地址发送 Key，不跟随 HTTP 重定向，不在日志或回复中输出凭据，不创建登录副本。HTTP 连接遵循系统代理环境变量；代理与网络可达性需在 AstrBot 运行环境中配置。

## Codex：额度、重置卡与自然刷新

### 功能

读取本机已登录 Codex 账号的额度分组、周期剩余比例和刷新时间，以及可用重置卡数量和接口返回的有效期。使用 `account/rateLimits/read`，按实际返回的分组与窗口显示；剩余比例为 `100 - usedPercent`，限制在 0–100%，缺失值显示“未知”。额度属于登录账号共享的使用状态，额外 credits 保留服务返回的单位，不换算成金额。

重置卡数量取 `availableCount`，到期判断只检查 `status=available` 且未过期的卡片。若只返回数量、不返回有效期，就显示数量而不猜测到期时间；插件不执行重置卡兑换。

### 配置步骤

1. 在 **AstrBot 运行环境** 安装 Codex CLI，并以 ChatGPT 账号登录。
2. 保持“启用 Codex 额度查询”开启；能从 PATH 找到 CLI 时保留 `codex_path=codex`，否则填写原生程序完整路径。
3. `codex_home` 留空继承运行环境，需要指定用户目录时填写该登录账号的 `.codex` 路径。
4. 保存配置并重载插件，用 `/codex额度` 验证；群内使用 `/codex-alarm` 开启刷新与到期提醒。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `codex_query_enabled` | `true` | 启用 Codex 额度查询；关闭后跳过手动查询和自动读取。 |
| `codex_path` | `codex` | CLI 名称或完整路径，只填程序路径，不填参数。 |
| `codex_home` | 空 | 留空继承 CLI 运行环境；可显式指定 `.codex` 用户数据目录。 |
| `codex_weekly_reset_reply` | 要重置了，快蹬喵 | Codex 周重置提醒，留空隐藏文字。 |
| `codex_card_expiry_reply` | 重置卡要过期了，快蹬喵 | Codex 重置卡过期提醒，留空隐藏文字。 |

**部署位置影响 Codex 查询：** 推荐 AstrBot 与 Codex 在同一台电脑、同一系统用户下运行。Windows 服务或其他用户需要配置可访问的 CLI 路径、Codex 用户目录；使用系统凭据库保存登录时，仅指向目录仍可能不足，须在对应运行用户下登录。

Docker 容器不能直接执行宿主机的 Windows `codex.exe`，也不会自动读取宿主机的登录身份。本版没有远程采集桥接：容器内需安装适用的 Codex CLI 并完成登录，才能查询该登录账号。DeepSeek 官方余额查询不要求与 Windows Codex 同机。

Windows 官方 npm 安装的 `codex.cmd` / `codex.ps1` 包装器可自动解析到原生程序。无法自动定位时，在插件配置中填写原生 `codex.exe` 完整路径。比如本次验证环境的路径为：

```text
C:\Users\你的用户名\AppData\Roaming\npm\node_modules\@openai\codex\node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\bin\codex.exe
```

该路径仅为示例，不会写入默认配置，CLI 更新后路径可能变化。`codex_home` 示例为 `C:\Users\你的用户名\.codex`。

本地 Codex 登录身份变化后，缓存可能保留到到期；可将 `cache_seconds` 设为 0 或重新加载插件。同一路径切换账号后，请重新查询以更新闹钟日期。

### 查询时的提醒

两条文案都可在配置中修改，同一条结果中每种提醒最多显示一次：

| 条件 | 默认文案 |
| --- | --- |
| 周剩余额度严格大于 50%，距离周自然刷新大于 0、不足 48 小时 | 要重置了，快蹬喵 |
| 至少一张可用重置卡距离过期大于 0、不足 48 小时 | 重置卡要过期了，快蹬喵 |

周期长度 `10080` 分钟视为周周期，不根据 5 小时窗口触发周提醒。恰好剩余 50% 或恰好 48 小时不触发上述查询时提醒；缓存有效期间按缓存数据的查询时间判断。下面的订阅闹钟有独立的提醒档位。

### 额度刷新与重置卡到期订阅

| 指令 | 功能 |
| --- | --- |
| `/codex-alarm` 或 `/codex-alarm on` | 开启当前群/私聊的额度刷新提醒，并读取最新 Codex 时间 |
| `/codex-alarm off` | 关闭当前会话提醒，清除待发送消息 |
| `/codex-alarm status` | 查看当前会话订阅和记住的刷新/到期时间 |

群管理员、群主或 AstrBot 管理员可操作和查看记录；私聊可自行订阅。订阅对应当前 `unified_msg_origin`，不会自动添加其他群。指令不调用模型，即使 DeepSeek 余额不足也能执行。该功能需要运行环境能够查询本机 Codex；监控的是本插件配置的登录账号，群内通知也是该账号的时间。

每次成功执行 `/额度`、`/codex额度` 或自然语言 Codex 额度查询，会记住接口返回的周刷新时间和重置卡有效期。只有周期长度 `10080` 分钟的窗口视为周额度；只记录 `status=available` 且有效期尚未到的重置卡，同一有效期的卡合并显示数量。接口缺少有效期时保留上次有效记录，不根据卡数量、全局公告或本地估计生成有效期；明确 `availableCount=0` 时清除旧卡记录。

Codex 额度查询开启时，全局 Reset 的 timeline 出现新的正式确认事件会重新查询本机 Codex 来更新记录，即使全局 Reset 的聊天提醒开关关闭也会执行。首次历史基线不触发；本机查询或保存失败则保留任务，下次 Reset 轮询再试。不把公告日期视为个人周刷新时间，也不认为所有账号已到账。

闹钟配置独立于全局 Reset 概率轮询，在 AstrBot 插件配置中修改后保存并重载插件：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `codex_alarm_poll_minutes` | 30 | 本地时间记录检查间隔，单位分钟，范围 1–1440 |
| `codex_alarm_reminder_hours_1` | 48 | 第一档提前提醒，单位小时，范围 1–720 |
| `codex_alarm_reminder_hours_2` | 24 | 第二档提前提醒，单位小时，范围 1–720 |

两个提醒时间同时用于周自然刷新和重置卡到期，自动排序去重。下面以默认 48h / 24h 为例：

- 周额度自然刷新和重置卡到期分别在进入 **48 小时内**、**24 小时内**时提醒，同一时间点的同一档位对每个订阅会话只发送一次。
- 查询、订阅或全局 Reset 重读后，若记录已经进入提醒窗口且该档尚未送达，立即提醒，不等待下一轮。初次记录已经不足 24 小时时，只发 24h 档；失败待发送的 48h 在进入 24h 后由最新档位替代。
- 正常持续运行到记录的自然刷新时间时，通过独立到点定时器发送通知，不必等待 30 分钟轮询。消息说明“已经到自然刷新时间啦喵”，并提示实际额度以 Codex 返回结果为准；它不声称服务已成功到账。
- 周刷新时间已到后立即重新读取接口，记住下一周期。启动、重连或查询时才发现已经错过刷新时间，且没有发送过到时通知，则只获取当前额度，不补发旧到时通知；新记录进入提前提醒窗口时仍按新时间处理。读取失败在后续轮询重试，至少间隔 5 分钟。开启订阅时未读到最新数据，也会保存订阅并稍后重试。
- 查询或全局 Reset 让未来周期/卡有效期发生变化时，旧的待发送提前提醒会失效。过期卡不会继续发送提前提醒；卡片可能已被使用，提醒始终注明依据上次查询记录并提示核实可用状态。
- 提前提醒发送失败时最多保留一天，并在日期仍有效时重试。到时通知只用于本次连续运行的定时器，允许 60 秒调度延迟；重启不恢复旧到时队列，重连后也不补发已错过的到时消息。关闭订阅清除该会话队列；重启恢复日期和送达记录，避免通常情况下重复提醒。

默认使用猫娘语气，并复用已有提醒图片开关和图片路径配置，例如：

```text
⏰ 周额度会在 48 小时内自然刷新啦，剩余的额度记得用起来喵！
额度分组：codex
刷新时间：{时间}（北京时间）
```

```text
🎟️ 记住的 1 张重置卡会在 24 小时内到期，快去看看还能不能开蹬喵！
到期时间：{时间}（北京时间）
这是上次查询记录的有效期，卡片是否仍可用请查看实际额度喵。
```

```text
🎉 周额度已经到自然刷新时间啦，可以去查看当前额度喵！
额度分组：codex
记录的刷新时间：{时间}（北京时间）
实际额度以 Codex 返回的结果为准喵。
```

数据保存在 `data/plugin_data/astrbot_plugin_account_quota/codex_alarm_state.json`，异步落盘并原子替换。修改 CLI 路径或 Codex 用户目录后重新加载，会保留订阅并清除旧路径下的时间；同一路径切换登录账号后请重新查询，记录会按新接口数据更新。不要在账号切换后依赖未更新的旧时间。

网络失败仅记录日志，单个群发送失败不影响其他群，有效的提前提醒待发送消息下轮重试；卸载等待保存完成并取消后台查询。发送成功和保存送达状态之间若发生异常退出，QQ 接口不能保证严格恰好一次，极端情况下该条可能重发。时间记录损坏时仅停用额度闹钟，保留文件供恢复，不覆盖旧数据。

关闭 Codex 额度查询会暂停手动查询、开启闹钟时和后台到点时的额度读取，以及全局 Reset 确认后的额度重读。订阅和已有日期保留，已有日期的提醒继续运行；需要同时关闭本群闹钟时，使用 `/codex-alarm off`。

## 福利重置预测：功能与配置

根据 codex-reset.com 提供的公开数据，显示未来 **24h / 48h** 发生全局福利 Reset 的概率、置信度、官方信号及已确认历史；达到预警档位时推送提醒。预测用于判断可能发生的时间窗口，不保证确切重置时刻或个人账号到账。

无需本地 Codex 登录或 DeepSeek API Key；即使关闭个人额度查询，也可单独使用预测、历史和订阅功能。

### 开启方式

1. 使用 `/codex-reset` 查看当前预测，使用 `/codex-reset history` 查看已确认历史。
2. 在目标群或私聊使用 `/codex-reset watch on` 开启订阅。
3. 默认每 60 分钟轮询，预警档位为 75% / 83% / 93%，不建议修改阈值；如需关闭新官方信号的单独提醒，使用 `/codex-reset signal off`。
4. 修改下方监控配置后保存并重载插件。

### 指令

| 指令 | 功能 |
| --- | --- |
| `/codex-reset` | 24h / 48h 概率、置信度、距上次 Reset 天数、时间、官方信号和更新时间 |
| `/codex-reset history` | 最近 5 条正式确认的 Reset |
| `/codex-reset history 10` | 指定历史条数，范围 1–20 |
| `/codex-reset watch on` | 订阅当前私聊或群聊 |
| `/codex-reset watch off` | 关闭当前会话订阅并清除待发送提醒 |
| `/codex-reset watch status` | 查看当前会话订阅状态与提醒配置 |
| `/codex-reset signal on` | 开启当前会话的新官方信号单独提醒 |
| `/codex-reset signal off` | 关闭单独信号提醒，跨档预警仍附当前信号状态 |
| `/codex-reset signal status` | 查看当前会话的信号提醒开关和监控配置 |

指令仍遵循 AstrBot 的唤醒前缀或 @ 唤醒设置；命中后直接返回，不调用 LLM。没有注册 `/codex` 别名，避免与个人额度查询混淆。

所有人可查询预测、历史和当前会话订阅状态。私聊用户可自行开启/关闭订阅；QQ 群中只允许当前群管理员、群主或 AstrBot 管理员操作。QQ 群角色使用 OneBot / aiocqhttp 的事件 `sender.role`，无法识别群角色的其他适配器仅允许 AstrBot 管理员修改群订阅。订阅只记录当前 `unified_msg_origin`，不会把其他会话加入订阅。

### 自动提醒与去重

- **预测**：同时检查 24h 与 48h，任一概率达到并向上跨过默认 75 / 83 / 93% 档位时提醒。普通 15%、28% 或低于 75% 的历史预测不推送；40→77 提醒，77→80 不提醒，80→85 提醒。75% 提示“距离上次重置已经有点久啦，未来很有可能会重置喵。”；83% 关注官方可能明确表示的 Reset 信号；93% 使用 Strong Watch 强提醒并注明“尚未确认到账”。官方表态与时间/日期以实际返回的信号为准，概率数值本身不证明官方已经给出日期。一次跨过多个档位只提醒最高档；更高档可立即提醒。跌回较低档后重新跨越同级，默认需等待 6 小时冷却。预测消息明确表示尚未确认、并非账号到账。
- **官方信号**：使用 `forecast.official_signal`，只提醒新的信号，且 24h / 48h 任一概率须达到预警阈值；与同轮跨档提醒合并为一条预警。优先按事件 ID 去重，无 ID 时按时间、内容和 URL 摘要去重。同一信号短暂消失再出现也不重复。这里的“官方信号”是来源站对公开官方发言的判断。
- **确认 Reset**：只有 timeline 中 `group == "reset"` 且 `announcement_state == "announced"` 的新事件才提醒；概率升高、普通帖子、预告和 banked 状态不替代正式确认。按事件 ID 和事件时间防止回退数据误报，已确认的同一事件不再作为“未确认信号”发送。预警三档及最终确认使用猫娘语气，固定提示句尾带“喵”；事件时间、摘要、链接和来源署名按原样显示。正式确认覆盖同轮预测，并清除尚未送达的旧预测/信号预警，避免确认之后又推送“未确认”。
- **首次启动**：首次成功获取历史后仅记录最近已确认事件，首次预测也仅建立基线，不推送历史 Reset、旧信号或当前概率。空历史和失败响应不建立历史基线。重启后恢复订阅及已读状态。

后台默认每 60 分钟（1 小时）尝试获取预测与历史，最短 1 分钟。手动查询与后台共用每个端点的锁和 60 秒缓存；失败也限频，429 同时遵守秒数或 HTTP 日期格式的 `Retry-After`。HTTP 超时为 15 秒，网络失败只写日志，不向聊天发送故障提醒。一个端点失败不阻止另一个端点的确认事件检测。卸载/重载会取消后台任务并关闭 HTTP 客户端。

订阅、最近 Reset、信号去重、阈值和待发送提醒保存到 AstrBot 官方插件数据目录 `data/plugin_data/astrbot_plugin_account_quota/reset_state.json`，使用异步线程和原子替换写入，不放在插件安装目录。状态损坏时停用 Reset 监控并记录日志，避免覆盖订阅数据；修复或备份后删除损坏文件，再重新加载。个人额度查询仍可使用。

各会话发送失败互不影响，失败消息保留并在下轮重试，最多保留一天、每会话最多 20 条待发送提醒。成功发送后保存送达状态；若发送成功与写入状态之间进程异常退出，恢复后可能重复这一条，QQ 发送接口无法保证严格的恰好一次送达。关闭订阅会清除该会话待发送队列。

### 监控配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `poll_interval_minutes` | 60 | 轮询分钟数，范围 1–1440；修改后重新加载 |
| `timezone` | Asia/Shanghai | 默认北京时间，其他 IANA 时区需系统时区数据库 |
| `probability_warning` | true | 概率档位提醒 |
| `threshold_1` / `threshold_2` / `threshold_3` | 75 / 83 / 93 | 24h / 48h 任一阈值；不建议修改，范围 1–100，自动排序去重 |
| `probability_cooldown` | 21600 | 同级重复提醒冷却秒数，范围 0–604800 |
| `signal_notification` | true | 新官方信号单独提醒的默认开关，会话指令设置优先 |
| `reset_notification` | true | 新正式确认事件提醒 |

群管理员、群主或 AstrBot 管理员可用 `/codex-reset signal on|off` 设置当前群的新官方信号单独提醒，私聊用户可自行设置。此开关与订阅独立：须先开启 `watch on` 才会收到推送。关闭后出现新信号不会单独发送；概率向上跨档时仍附当前信号状态，最终确认提醒保留。会话设置持久化并优先于配置默认值，旧版状态文件升级时保留订阅和去重记录。

监控配置修改后请重新加载插件。轮询配置现以分钟为单位。旧版 `poll_interval` 秒数字段保留用于一次性迁移，首次升级加载时自动转换为分钟（不足一分钟向上取整），随后旧字段归零。已设置的非默认分钟数优先；升级后请核对分钟配置，无需修改兼容字段。现有 DeepSeek USD 显示、账号额度提醒文案、默认提醒图片及自定义图片配置继续有效；全局 Reset 推送使用文字消息。

### 数据来源与风险

仅使用站点公开 GET JSON API：[forecast](https://codex-reset.com/api/forecast)、[timeline](https://codex-reset.com/api/timeline?locale=zh)。信号直接使用 forecast，不额外轮询可选 feed。接口无需 Key、不解析 HTML、不使用浏览器爬虫，也不消耗模型额度。请求使用标识本插件及 GitHub 仓库的 User-Agent。

所有 Reset 查询、订阅结果与通知均包含来源链接，并以 `Data: codex-reset.com` 结尾，遵循[数据源开发者规范](https://codex-reset.com/developers)。历史摘要采用接口文档承诺的 `summary`，可能为英文；时间默认转换为北京时间。

本插件与 OpenAI、Codex、codex-reset.com 官方均无隶属关系。Reset 概率只是第三方预测，不代表一定发生；“已确认”表示来源站 timeline 满足上述筛选条件，不证明你的个人账号已经到账。接口可能延迟、误分类或变更，账号实际额度请通过 `/codex额度` 或 Codex 客户端查看。

### 提醒文案与图片

个人额度查询触发提醒时及额度闹钟通知时，默认附带一张图片。内置图片位于 `assets/default_reminder.png`，也可改成自己的图片；全局福利 Reset 推送使用文字消息。

在插件管理页配置：

- **DeepSeek 余额不足提醒文案**：修改人民币总余额不足 10 元时的提示。
- **Codex 周额度即将重置提醒文案**：修改周重置提醒。
- **Codex 重置卡即将过期提醒文案**：修改重置卡过期提醒。
- **提醒时附带图片**：默认开启，关闭后仅发送文字。
- **提醒图片路径或 URL**：留空使用内置图，也可填写自己图片的路径或 URL。

自定义图片示例：

```text
Windows 本地绝对路径：D:\Pictures\quota.png
Linux / Docker 内路径：/app/data/quota.png
相对插件目录的路径：assets/my_reminder.png
网络图片：https://example.com/quota.png
```

本地路径必须能被 AstrBot 运行环境读取；Docker 中填写容器内路径。网络图片需可被 AstrBot 或消息适配器读取，最终图片发送能力取决于消息平台。配置的本地图片不存在或路径无效时，仅发送文字，并在日志提示检查配置。

普通查询、查询失败和权限不足不附图。同一条汇总结果中，即使多个提醒同时触发，也只附一张图。留空某条提醒文案会隐藏该条文字，但只要提醒条件成立，仍遵循图片开关。文案在输出时读取配置，缓存结果不会锁住旧文案；保存配置并重新加载插件后使用新设置。
